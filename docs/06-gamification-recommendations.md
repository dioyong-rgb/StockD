# StockD 게임화 확장 추천

검토일: 2026-10-05, Asia/Seoul.

현재 HTML 시안과 프로젝트 문서를 확인하고, 실제 서비스의 공식 안내와 게임화 연구를 참고한 제안이다. 이 문서는 추천과 도입 조건을 정리하며, 화면이나 실제 연동을 새로 구현한 결과를 뜻하지 않는다.

## 1. 추천 방향

첫 확장으로 **상황 판단 연습 + 선택형 숙련 지도 + 상자 캐릭터 성장·꾸미기**를 추천한다. 업무를 익힐수록 새로운 모습을 얻고, 다음에 배울 내용을 직접 고르는 흐름이다. 현재 샘플만으로 체험할 수 있어 API 준비와 독립적으로 검토하기 좋다.

이후 지속 저장을 갖추면 주간 목표를 추가하고, 실제 수집과 내부 기록이 검증되면 상황별 미션을 연결한다. 여러 운영자가 함께 사용하는 단계에서 팀 협동 목표를 도입한다.

## 2. 현재 있는 요소와 확장 출발점

현재 프로젝트는 설계와 단일 HTML 시안 단계다. 실제 앱·DB·수집기·쇼핑몰 API 연동은 없다. 확인 근거는 [README](../README.md), [HTML](../preview/index.html), [샘플 미션 검증 문서](prototype-gamification-verification.md)이며, 저장된 데스크톱 캡처도 참고했다. 이번 검토에서 기존 동작 검증을 다시 실행하지 않았다.

| 이미 있는 요소 | 현재 의미 | 추가할 가치 |
| --- | --- | --- |
| 고정 미션 3개 | 재고·조회 상태 검토, 옵션 3개 연결 체험 | 다양한 상황과 선택 가능한 목표 |
| 진행률 0/3 | 현재 화면의 샘플 검토 진행 | 분야별 학습 성장과 주간 누적 기록 |
| 배지 2개 | 첫 연결 체험, 한 바퀴 검토 | 조건이 분명한 분야별 성취와 꾸미기 해금 |
| 상자 안내 캐릭터 | 정적 그림과 진행 안내 | 성장 단계, 스티커·액세서리 선택 |
| 효과 사용 설정 | 전환 효과를 줄이는 설정 | 게임 요소 전체를 접거나 끄는 선택 |

새로고침하면 샘플 진행이 초기화된다. 장기간의 레벨·주간 기록·팀 성취를 제공하려면 별도의 지속 저장이 필요하다.

확장 전에 배지 규칙도 맞추는 편이 좋다. 설계 문서는 배지 3개와 연결 해제 후 배지 복귀를 설명하지만, 실제 HTML과 검증 문서는 배지 2개와 당시 성취 유지를 사용한다. 특히 HTML의 `한 바퀴 검토`는 재고·조회 검토와 관계없이 옵션 3개 연결만으로 획득한다. 이를 `옵션 3개 연결 체험`으로 바꾸거나, 세 미션 모두 완료하는 조건으로 통일하는 것을 추천한다. 이 문서의 현재 상태 설명은 실제 HTML을 기준으로 했다.

## 3. 후보 비교

난이도는 현재 시안에 체험을 추가하는 상대적인 수준이며, 개발 시간 견적은 아니다.

| 요소 | 구체적인 경험 | 기대하는 도움 | 시안 난이도 | 지속 운영에 필요한 조건 |
| --- | --- | --- | --- | --- |
| 상황 판단 연습·숙련 지도 | `0`, `—`, 이전 성공값을 구분하고 재고·조회·주문 분야를 선택 | 수량과 상태를 잘못 읽는 실수 줄이기 | 중간 | 시나리오 정답 검토, 사용자별 학습 기록 |
| 캐릭터 성장·작업대 꾸미기 | 연습 완료로 상자 스티커·모자·선반 장식 해금 | 성취를 눈에 보이게 표현하고 수집 재미 제공 | 낮음~중간 | 중복 해금 방지, 선택과 성취 저장 |
| 선택형·상황별 미션 | 오늘의 후보 중 1~3개 선택, 실제 연동 후에는 오래된 조회·미연결 옵션 우선 제안 | 반복되는 고정 미션을 현재 업무와 연결 | 중간 | 검증된 수집 결과, 내부 검토 기록, 권한과 이력 |
| 주간 누적 목표·성취 회고 | 이번 주 새로운 사례 3개, 내가 고른 업무 2건의 검토 근거 기록 | 쉬어도 유지되는 꾸준한 진행 | 중간 | 날짜·사용자별 지속 저장, 목표 조정 |
| 팀 협동 목표 | 팀에서 선택한 옵션 10개의 연결 근거 검토 | 공동 점검과 인수인계 지원 | 높음 | 다중 사용자·역할·권한·공유 목표·감사 이력 |

위 효과는 StockD에서 확인된 성과가 아닌 설계 가설이다. 사용성 검토에서 실제 도움이 되는지 확인해야 한다.

## 4. 먼저 넣을 게임 경험

### 4.1 상황 판단 연습과 숙련 지도

현재 검토 버튼 앞에 선택형 연습을 추가하거나 별도 연습 영역을 제공한다. 업무 화면은 언제든 사용할 수 있고, 연습 순서는 사용자가 고른다. 시간 제한과 오답 벌점은 두지 않는다. 틀리면 설명을 보고 다시 시도한다.

| 연습 분야 | 샘플 질문 | 확인할 이해 |
| --- | --- | --- |
| 재고 읽기 | 정상 조회에서 수량이 0이면 어떤 상태인가? | 품절과 조회 실패를 구분 |
| 조회 실패 | 첫 조회 실패의 `—`를 0으로 읽어도 되는가? | 수량 미확인과 실제 0을 구분 |
| 최신성 | 마지막 성공값 7개, 최근 조회 실패라면 무엇을 함께 봐야 하는가? | 이전 값과 마지막 성공 시각·지연 상태를 함께 확인 |
| 지원 범위 | 재고 관리 미사용과 미지원 수량을 보유 재고로 합산할 수 있는가? | 수량의 의미와 조회 지원 여부를 확인 |
| 주문·클레임 | 주문 3개 중 1개 클레임이면 주문 전체가 취소되었다고 볼 수 있는가? | 부분 클레임과 전체 주문 상태를 구분 |
| 로켓그로스 주문 | 출고 이후 조회 목록에 없으면 신규 주문이 없다고 단정할 수 있는가? | 조회 범위의 한계를 이해 |

숙련 지도는 `재고 읽기`, `조회 신뢰성`, `SKU 연결`, `주문·클레임` 네 가지 경로로 구성한다. 경로마다 처음 완료한 서로 다른 연습을 표시하고, 분야별 배지는 무엇을 익혔는지 설명한다. 연습 배지는 실제 API 연결 성공이나 재고 정상 상태를 뜻하지 않는다.

### 4.2 기존 상자 캐릭터의 성장과 꾸미기

상자 캐릭터를 그대로 활용한다. 작은 상자 → 도구를 든 상자 → 장식된 작업대처럼 누적 성취가 보이는 모습을 제공한다. 단계 명칭은 학습 성장으로 표시하고 실제 직원 역량 인증처럼 표현하지 않는다.

보상 예시는 민트 스티커, 돋보기, 작은 모자, 선반 배경이다. 사용자가 획득한 장식 중 원하는 것을 고른다. 조금 더 게임 같은 분위기를 원하면 작은 가상 창고의 장식이 늘어나는 형태로 확장할 수 있다. 가상 창고는 학습 성취를 표현하며 실제 창고 재고·수집 정상 여부와 연결하지 않는다.

경험치를 사용한다면 규칙은 단순하게 둔다. 예를 들어 위 연습 6개를 제공할 때 서로 다른 연습의 최초 정답 완료에 각각 10 XP를 부여하고, 30 XP와 60 XP에서 모습을 해금한다. 이 숫자는 체험용 제안값이다. 오답 후 재시도에 감점하지 않고, 동일 연습 반복·메뉴 방문·상세 열기·알림 읽음에는 경험치를 추가하지 않는다.

기존 미션 영역 안에 캐릭터·짧은 성장 표시·꾸미기 버튼을 배치한다. 꾸미기 목록은 눌렀을 때 열고, 재고 표 위에 큰 보상 화면을 추가하지 않는다. 모바일에서는 한 줄의 성장 표시로 줄인다. 게임 요소 전체 숨기기와 움직임 줄이기를 지원하며, 업무 경고는 항상 보인다.

### 4.3 선택형 미션에서 실제 상황별 미션으로 확장

시안에서는 6개 정도의 연습·검토 후보 중 관심 분야의 1~3개를 선택하게 한다. `재고 보기`, `조회 상태`, `주문 이해` 등의 묶음을 고를 수 있다. 업무가 없는 날에는 연습을 선택할 수 있지만 강제로 채우지는 않는다.

실제 연동 후에는 최근 데이터에 따라 오래된 조회 확인, 미연결 옵션 근거 검토, 부분 클레임 상태 확인 등을 제안한다. 높은 위험의 업무는 사용자의 미션 선택 여부와 관계없이 기존 알림과 업무 목록에 남긴다.

보상 조건은 대상·자료 시점·분류 결과·검토 근거의 내부 저장으로 정한다. 단순한 읽음이나 완료 클릭을 운영 문제 해결로 인정하지 않는다. 조회 복구·부족 재고 해소 같은 실제 상태 변화는 신선하고 유효한 원천 데이터로 별도 판정한다. 자동 수집 복구를 특정 사용자의 공로로 돌리지 않는다.

### 4.4 주간 누적 목표와 짧은 회고

`이번 주 새로운 연습 3개`, `선택한 옵션 2개의 검토 근거 기록`처럼 사용자가 조정하는 목표를 제공한다. 연속 출석을 요구하지 않고 이미 얻은 레벨·장식은 쉬어도 유지한다. 휴일·휴가·업무 없음은 벌점 대상이 아니다.

활동 기록과 운영 상태를 각각 보여 준다. 예를 들어 `이번 주 검토 근거 2건 기록` 옆에 `현재 조회 지연 1건`을 표시할 수 있지만 두 값을 하나의 건강 점수로 합치지 않는다. API 오류나 권한 부족으로 수행할 수 없는 항목은 대기 사유를 표시한다.

주간 목표와 성취 기록은 지속 저장을 만든 다음 도입한다. 초기 HTML 체험에서는 샘플 주간 기록임을 명시한다.

### 4.5 팀 협동 목표는 다중 사용자 단계에 도입

팀이 특정 대상 목록을 정하고 검토 기록을 나누어 남기는 방식이다. 예를 들어 `선택한 미연결 옵션 10개 검토`와 각 항목의 기여자를 표시한다. 사용자 수나 매출이 다른 운영자를 한 순위표로 비교하지 않는다.

조회자는 검토 기록만 남기고, 실제 내부 SKU 매핑 변경은 허용된 역할이 승인한다. 한 항목은 팀 목표에 한 번만 반영하며, 다른 구성원의 미완료로 개인의 기존 보상을 차감하지 않는다. 로그인·조직 권한·영속 이력을 갖춘 이후 검토한다.

## 5. 보상과 데이터 판정 기준

| 사건 | 인정하는 성취 | 처리 기준 |
| --- | --- | --- |
| 서로 다른 샘플 연습을 처음 정답 완료 | 학습 경험치·연습 배지 | 사용자·시나리오·버전에 따라 중복 지급 방지 |
| 실제 자료의 검토 근거를 내부 기록에 저장 | 검토 수행 이력 | 동일 사건의 같은 자료에 재기록해도 중복 보상하지 않음 |
| 승인 권한자가 내부 SKU 연결을 저장 | 내부 연결 이력 | 승인 결과와 원본 옵션·내부 SKU를 기록, 해제·재연결 반복으로 보상 증가 방지 |
| 신선한 원천 데이터로 실제 상태 복구 확인 | 운영 상태 갱신 | 단순 검토·읽음과 구분, 자동 복구를 개인 점수로 사용하지 않음 |
| API 실패·미지원·권한 부족·부분 수집 | 제한 또는 대기 상태 | 수량 0·미션 실패·사용자 감점으로 바꾸지 않음 |

샘플 성취와 운영 성취는 출처를 명확히 표시한다. 실제 재고 0, 오류, 오래된 값, 미지원, 미연결 상태는 미션을 완료해도 유지한다. 첫 버전의 모든 미션은 조회·학습·내부 검토 범위로 한정하며 쇼핑몰 재고 수정·발송·주문 상태 변경을 요구하지 않는다.

## 6. 추천 도입 순서와 확인 방법

1. 현재 배지 이름·완료 조건과 문서를 맞춘다.
2. 샘플 상황 판단 연습 6개, 선택형 숙련 지도, 캐릭터 장식 몇 개를 하나의 체험으로 만든다.
3. 게임 요소를 접거나 끌 수 있게 하고 360px 모바일·키보드·움직임 줄이기에서 업무 이용을 확인한다.
4. 사용자와 지속 저장을 갖춘 뒤 주간 목표·누적 성장 기록을 추가한다.
5. 실제 수집·검토 기록이 검증된 다음 상황별 미션을 연결하고, 다중 사용자 단계에서 협동 목표를 검토한다.

검토 지표는 체류 시간보다 상태 구분 정확도, 올바른 후보를 판단하는 비율, 잘못된 연결·재검토 발생, 주요 업무를 찾는 시간, 사용자가 느끼는 부담을 우선한다. 가능하면 같은 사례를 기본 화면과 게임 요소를 포함한 화면에서 번갈아 수행하게 한다. 이해가 좋아져도 업무 시간이 늘거나 부담이 커지면 게임 영역을 줄인다. 표본과 과제 수를 기록하고 작은 사용성 검토를 생산성 향상 수치로 일반화하지 않는다.

## 7. 조사 근거와 적용 판단

아래 자료는 요소 선택의 참고 근거이며 StockD의 업무 효율 개선을 증명하지 않는다. 공개 자료 확인일은 2026-10-05이다.

- **요소별로 다른 효과:** Sailer 등의 창고 주문 피킹 온라인 시뮬레이션 연구는 배지·순위·성과 그래프 묶음이 유능감과 과제 의미에, 아바타·이야기·동료 묶음이 관계감에 영향을 주었다고 보고한다. 개별 요소의 효과나 실제 운영 생산성 향상을 입증한 결과로 해석하지 않는다. 온라인 공개일은 2016-12-23, 학술지 게재연도는 2017년이다. [논문 원문 PDF](https://d-nb.info/1309619042/34)
- **연속 기록의 중단과 복구:** Silverman·Barasch의 7개 연구에서는 연속 달성 유지·중단을 기록에 표시하는 방식이 이후 참여에 영향을 주었으며, 중단을 자기 책임으로 느낄 때 차이가 커지고 복구 가능성이 있으면 완화되었다. 이를 참고해 StockD에는 휴일·수집 장애로 누적 성장을 초기화하지 않는 목표를 제안한다. 온라인 공개일은 2022-06-30, 학술지 게재연도는 2023년이다. [저자가 공개한 논문 원문 PDF](https://www.jackiesilverman.com/_files/ugd/0399b5_58713e2052ca4148891dbb00b30a8597.pdf?index=true)
- **학습·실습과 성장 연결:** Salesforce Trailhead는 퀴즈·실습 결과 확인을 배지·포인트·성장 단계에 연결한다. StockD에는 단순 클릭보다 상황 판단 연습과 분야별 숙련 지도에 적용할 수 있다고 판단했다. [공식 안내](https://trailhead.salesforce.com/content/learn/modules/trailhead-for-companies/get-started-using-trailhead-in-your-company)
- **목표의 조정과 휴식:** Todoist는 일간·주간 목표, 게임화 끄기, 쉬는 요일과 휴가 모드를 제공한다. StockD에는 사용자가 조정하는 주간 누적 목표와 휴식 시 보상 유지에 적용할 수 있다고 판단했다. 문서 갱신일은 2026-08-28이다. [공식 생산성 안내](https://www.todoist.com/help/todoist/features/use-the-productivity-view-in-todoist-6S63uAa9)
- **성장 보상의 꾸미기:** Todoist는 일정 성장 단계에 도달하면 테마를 해금한다. StockD에서는 기존 상자 캐릭터의 장식과 작업대 배경을 해금하는 방식으로 응용할 수 있다. 문서 갱신일은 2026-08-28이다. [공식 Karma 안내](https://www.todoist.com/help/todoist/features/introduction-to-karma-OgWkWy)

StockD에 대한 추천 우선순위와 보상 규칙은 프로젝트의 조회 중심 범위, 현재 화면, 데이터 상태 원칙을 바탕으로 정한 설계 판단이다.
