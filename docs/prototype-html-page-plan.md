# HTML 페이지·메뉴 구성 계획

- 작성일: 2026-10-12
- 상태: 계획 (구현 전)
- 근거: [12-work-plan.md](12-work-plan.md)의 결정 D1(게임 요소 포함), D2(로그인은 화면·메뉴만), D5(세미콜론 없음), 기존 시안 `preview/index.html`
- 범위: **메뉴 구조와 정적 HTML 페이지만** 만든다. 서버, DB, API, 실제 인증, Next.js 이관은 이 계획에 포함하지 않는다.

## 1. 목표와 원칙

- 목표: 첫 버전 전체 화면을 눈으로 확인할 수 있는 다중 페이지 정적 HTML 세트를 만들고, 이후 Next.js 컴포넌트 이관(WS6)의 기준으로 쓴다.
- 기존 `preview/`(단일 파일 시안)는 수정하지 않고 보존한다. 새 세트는 `ui/` 폴더에 만든다.
- 모든 데이터는 가상 샘플(`DEMO-*`)이며 모든 페이지 상단에 "샘플 데이터 · 실제 API 미연동"을 표시한다.
- 쇼핑몰 쓰기 기능(재고 수정, 발송, 주문 상태 변경) 화면과 버튼은 만들지 않는다.
- 로그인은 화면과 사용자 메뉴만 만들고 "인증 미구현 · 화면 시안"을 표시한다. 입력값은 어디로도 전송·저장하지 않는다.
- 반응형 필수: 360px(카드), 768px(축약 표), 1440px(상세 표).
- 코드 스타일: 들여쓰기 2칸, JS 세미콜론 없음, 주석 한국어, 변수·함수명 영어, `any` 해당 없음.
- 외부 라이브러리·CDN·빌드 도구를 쓰지 않는다. 외부 요청은 0건이어야 한다.

## 2. 메뉴 구조 (정보 구조)

| 순서 | 메뉴 | 파일 | 용도 |
|---|---|---|---|
| 1 | 대시보드 | `index.html` | 운영 요약, 확인 필요 항목, 연결 상태, 매일 확인 요약 줄 |
| 2 | 통합 재고 | `inventory.html` | 옵션별 채널 재고 비교, 필터, 상세 |
| 3 | 통합 주문 | `orders.html` | 채널·기간·상태 필터, 부분 클레임, 상세 |
| 4 | 상품 연결 | `mappings.html` | 내부 SKU 연결 후보, 미연결 옵션, 이력 |
| 5 | 알림 | `alerts.html` | 재고·조회·연결 알림, 이력 |
| 6 | 연결·설정 | `settings.html` | 채널 계정 상태, 임계값, 샘플 초기화 |
| 7 | 매일 확인 | `missions.html` | 매일 미션, 최근 7일 스탬프, 연재 이야기, 배지, 샘플 연습 |
| - | 로그인 | `login.html` | 로그인 폼 화면 (인증 미구현) |
| - | 상태 예시 | `states.html` | 로딩·빈 화면·오류·지연·부분·권한 없음 6종 모아 보기 |

- 사이드바 순서는 업무 화면(1~6)을 먼저, 부가 기능(7)을 마지막에 둔다. 게임 요소가 업무 화면 앞이나 경고 위를 차지하지 않게 한다(R4 대응).
- 대시보드의 매일 확인은 한 줄 요약(진행 `n/3`, 이야기 이어 보기 링크)으로만 두고, 상세는 `missions.html`에서 보여 준다.
- 상단바: 작업 공간명 [샘플], 기준일, "쇼핑몰 조회 전용" 표시, 사용자 메뉴(가상 계정 `DEMO-user`, 로그인 화면 이동, 로그아웃 자리). 사용자 메뉴에는 "인증 미구현" 배지를 둔다.
- 960px 미만에서는 사이드바를 상단 가로 메뉴로 전환한다(기존 시안 방식 유지).

### 2.1 공통 영역과 공통 페이지

모든 페이지에 `layout.js`가 같은 방식으로 삽입한다. 변경은 한 곳에서 끝난다.

| 영역 | 내용 |
|---|---|
| 샘플 띠 | 최상단. "샘플 데이터 · 실제 API 미연동" |
| 상단바 | 작업 공간명, 기준일, "쇼핑몰 조회 전용", 사용자 메뉴, 도움말 링크 |
| 사이드바 | 업무 메뉴 7개 (공통 페이지는 넣지 않음) |
| 푸터 | 카피라이트, 서비스 한 줄 설명, 공통 페이지 링크, 샘플·버전 표기 |

| 공통 페이지 | 파일 | 진입 위치 | 내용 |
|---|---|---|---|
| 회사 소개 | `about.html` | 푸터 | 서비스 소개(조회 전용 통합 재고·주문), 제공 범위, 지원 채널, 하지 않는 일(외부 쓰기 없음), 회사 정보 자리표시자 |
| 도움말 | `help.html` | 상단바, 푸터 | 재고 상태 8종 설명, 수량 종류 설명, 자주 묻는 질문, 문의 안내 자리표시자 |
| 이용약관 | `terms.html` | 푸터 | 법무 검토 전 샘플 문안 틀 |
| 개인정보처리방침 | `privacy.html` | 푸터 | 법무 검토 전 샘플 문안 틀. 주소·전화·수취인 기본 미저장, 키 서버 보관 원칙 반영 |
| 오류 페이지 | `404.html` | 잘못된 주소 | 길 안내와 대시보드 이동 |

- 자리표시자 규칙: 회사명은 `[회사명 입력 필요]`, 주소·전화·사업자번호는 `[입력 필요]`, 이메일은 예약 도메인 `contact@example.com`(예시)으로 둔다. 사실처럼 보이는 회사 정보를 지어 넣지 않는다.
- 카피라이트: `© 2026 [회사명 입력 필요]. All rights reserved.` 연도는 `layout.js`가 기준년(2026)으로 고정해 표시한다(샘플 기준일과 일치).
- 법률 페이지 상단에 "법무 검토 전 샘플 문안입니다. 서비스 개시 전에 교체해야 합니다." 띠를 항상 표시한다.
- 개인정보처리방침 문안은 `docs/01-system-design.md` 보안 절(주소·전화·수취인 기본 미저장, 원본 보관 7일 제안값)을 근거로 하되 "제안값"임을 표시한다.

## 3. 폴더·파일 구조

```text
ui/
  index.html            대시보드
  inventory.html        통합 재고
  orders.html           통합 주문
  mappings.html         상품 연결
  alerts.html           알림
  settings.html         연결·설정
  missions.html         매일 확인 (미션·이야기·배지·연습)
  login.html            로그인 화면
  states.html           UI 상태 6종 예시
  about.html            회사 소개
  help.html             도움말
  terms.html            이용약관 (샘플)
  privacy.html          개인정보처리방침 (샘플)
  404.html              오류 페이지
  assets/
    tokens.css          색상·간격·글꼴 변수 (디자인 토큰 한 곳)
    base.css            리셋, 공통 레이아웃, 표, 폼, 다이얼로그
    components.css      배지, 카드, 알림 띠, 빈 상태, 진행 막대
    layout.js           사이드바·상단바 공통 삽입, 현재 메뉴 표시
    mock-data.js        가상 샘플 데이터 (재고, 주문, 연결, 알림)
    table.js            필터, 검색, 정렬, 상세 다이얼로그 공용 동작
    missions.js         매일 미션·이야기·배지 로직 (localStorage)
    story-data.js       연재 이야기 15컷 본문과 SVG
```

- 공통 영역(사이드바·상단바)은 `layout.js`가 `<div id="app-shell">`에 삽입한다. 페이지마다 복사하지 않아 메뉴 변경이 한 곳에서 끝난다.
- 색상은 `tokens.css`에만 정의한다. 기본은 현행 시안의 민트 계열(#247D68 / #16816A)이며, D7(디자인 토큰) 결정이 바뀌면 이 파일만 고친다.
- `file://`로 열어도 동작해야 한다(모듈 import, fetch 사용 금지). 스크립트는 일반 `<script src>`로 불러온다.

## 4. 페이지별 구성

### 4.1 공통 요소 (전 페이지)

- 상단 띠: "샘플 데이터 · 실제 API 미연동"
- 사이드바/가로 메뉴, 상단바, 사용자 메뉴
- 본문 위 안내: 표가 넓을 때 "표를 좌우로 움직여 확인하세요."
- 키보드 조작, 다이얼로그 Escape 닫기와 초점 복귀, 조작 영역 44px 이상, `prefers-reduced-motion` 지원

### 4.2 대시보드 (`index.html`)

| 영역 | 내용 |
|---|---|
| 확인 필요 요약 | 품절·부족, 조회 실패·지연, 미연결 옵션 개수 카드 3~4개 (각 카드는 해당 필터가 적용된 페이지로 이동) |
| 연결 상태 | 네이버, 쿠팡 판매자배송, 쿠팡 로켓그로스 각각 "실제 미연결" 표시와 마지막 성공 시각 |
| SKU별 채널 재고 비교 | BAG-NT-S, MUG-IV-320, BOX-GR-M, TAPE-IV-01 비교 표 (수량 종류 분리 표시) |
| 최근 알림 | 최신 3건과 알림 페이지 링크 |
| 매일 확인 한 줄 | 오늘 `n/3`, 이야기 이어 보기 링크. 경고 영역보다 아래에 배치 |

### 4.3 통합 재고 (`inventory.html`)

- 필터: 검색, 쇼핑몰, 배송 방식(판매자/로켓그로스), 상태, 결과 건수, 필터 초기화
- 표 열: 옵션, 내부 SKU, 채널·계정, 수량 종류(채널 등록 / 주문가능), 수량, 조회 상태, 마지막 성공 시각
- 상태 8종 배지: 정상, 부족, 품절, 확인 지연, 조회 실패, 미지원, 관리 미사용, 지원 미확인
- 규칙: 실패·미지원은 수량 칸을 `—`로 비우고 0으로 표시하지 않는다. 채널 수량을 합산한 값은 만들지 않는다.
- 행 클릭 시 상세 다이얼로그 (원본 식별자, 마지막 시도·성공 시각, 상태 설명)

### 4.4 통합 주문 (`orders.html`)

- 필터: 검색, 쇼핑몰, 배송 방식, 상태, 기간(from/to)
- 표 열: 주문번호, 일시, 채널·배송, 상품·옵션, 수량, 원본 상태, 클레임(부분 클레임 수량)
- 로켓그로스 안내: "출고 이후 조회되는 주문만 표시" 경고 띠
- 행 클릭 시 상세 다이얼로그. 상태 변경·발송 등 쓰기 버튼은 두지 않는다.

### 4.5 상품 연결 (`mappings.html`)

- 연결 후보 목록(옵션별 내부 SKU 후보 2개 이상), 선택 후 "시안에 연결 적용", 해제
- 미연결 옵션 목록과 연결 이력 표
- 안내: "샘플 내부 연결만 시연합니다." 새로고침 시 초기화

### 4.6 알림 (`alerts.html`)

- 탭: 미확인 / 전체. 유형 필터: 재고, 조회, 연결
- 항목: 제목, 설명, 시각, 관련 항목 이동 링크, "예시 확인"(읽음), 전체 확인
- 알림 확인과 게임의 "검토 기록"은 문구와 버튼 모양을 구분해 혼동을 막는다.

### 4.7 연결·설정 (`settings.html`)

- 채널 계정 패널(네이버, 쿠팡): 상태 "실제 미연결", 키·조회 권한 "미등록". **API 키 입력창은 두지 않는다.**
- 연결 절차 안내(준비 → 인증 → 조회 → 검증)
- 내부 설정: 수량 강조 기준(기본 5, 잘못된 값 거부), 효과 사용 토글, 샘플 초기화, 일일 기록 삭제(두 버튼은 분리)

### 4.8 매일 확인 (`missions.html`)

- 오늘의 미션 3단계(페이지 열기, 재고 화면 방문, 주문 화면 방문), 진행 막대, 최근 7일 스탬프
- 상자 친구 연재 이야기: 3편 15컷, 컷 목록(잠김은 텍스트·비활성), 읽기 다이얼로그
- 배지 2종, 추가 샘플 연습 3종(접힘)
- 고정 안내: "화면 방문 기록일 뿐 실제 재고 점검이나 API 정상 여부를 뜻하지 않습니다." 이야기는 허구임을 표시한다.
- 저장: `localStorage` 키 `stockd.daily-checks.v1`, `stockd.story-progress.v1`(기존 시안과 동일 규격). 저장 차단 환경에서는 현재 열기에서만 유지하고 안내한다.
- 이 페이지가 아닌 재고·주문 페이지 방문도 일일 미션 단계로 기록되도록 `missions.js`를 공통 로드한다.

### 4.9 로그인 (`login.html`)

- 이메일, 비밀번호 입력 폼과 검증 문구(형식만 확인)
- "인증 미구현 · 화면 시안" 배지, 제출 시 "실제 로그인은 아직 연결되지 않았습니다" 안내만 표시. 입력값 미전송·미저장
- 사이드바 없이 단독 레이아웃, "샘플로 둘러보기"로 대시보드 이동

### 4.10 상태 예시 (`states.html`)

- 6종: loading, empty, error, stale, partial, unauthorized를 각각 카드로 표시
- 재고·주문 페이지는 `?state=empty|error|loading|stale|partial|unauthorized` 쿼리로 같은 상태를 재현할 수 있게 한다.

### 4.11 공통 페이지 (`about.html`, `help.html`, `terms.html`, `privacy.html`, `404.html`)

- 공통 레이아웃(사이드바 포함)을 쓰고 사이드바에서는 활성 메뉴를 표시하지 않는다.
- 회사 소개: 서비스 한 줄 소개, 3단 카드(조회 전용 / 상태 구분 / 마지막 성공값 유지), 지원 채널 표(네이버, 쿠팡 판매자배송·로켓그로스 / G마켓·옥션·11번가는 "후속 확장"), 회사 정보 표(자리표시자)
- 도움말: 재고 상태 8종 표(라벨·의미·수량 표시 방식), 수량 종류 설명(합산하지 않는 이유), FAQ 6~8개(접이식 `<details>`), 문의 안내(자리표시자)
- 이용약관·개인정보처리방침: 목차 + 조항 제목 + 짧은 샘플 문단, 상단 "법무 검토 전 샘플" 띠
- 404: 안내 문구와 대시보드·도움말 이동 링크

## 5. 데이터 구성 (`mock-data.js`)

- 기존 시안의 재고 10건, 주문 6건, 연결 후보 3건, 알림 5건을 이관하고 다음을 보강한다.
  - 미연결 옵션 목록, 연결 이력
  - 대시보드 요약용 집계 (샘플 데이터 기준임을 표시)
- 모든 외부 ID는 `DEMO-*` 형식. 실제 상품명·고객 정보·키는 넣지 않는다.
- 상태 값은 `docs/01-system-design.md`의 이름(`valueState`, `readState`, `freshness`, `sourceMode`)을 코드 주석에 대응 표기하여 이후 이관이 쉽게 한다.

## 7. 완료 기준

- 14개 HTML 파일이 `file://`와 로컬 정적 서버 양쪽에서 열리고, 사이드바 메뉴 7개, 로그인 이동, 푸터 링크(회사 소개·도움말·이용약관·개인정보처리방침)가 모두 동작한다.
- 모든 페이지에 푸터 카피라이트가 보이고, 회사 정보는 자리표시자로만 표시되며 사실처럼 보이는 값이 없다. 법률 페이지에는 "법무 검토 전 샘플" 띠가 있다.
- 360/768/1440 폭에서 가로 스크롤은 표 영역 안에서만 생기고 본문 레이아웃이 깨지지 않는다.
- 모든 페이지에 샘플 배지가 보이고, 쓰기 버튼·API 키 입력창·외부 요청이 없다.
- 재고 상태 8종과 UI 상태 6종이 화면으로 구분된다. 실패·미지원은 0으로 표시되지 않는다.
- 게임 요소가 경고·품절·미연결 표시를 가리지 않는다(대시보드에서 업무 영역 아래).
- 키보드만으로 메뉴, 필터, 다이얼로그를 조작할 수 있고 Escape 후 초점이 돌아온다.
- 검증 스크립트가 PC 경로 하드코딩 없이 실행되고, 브라우저 오류 0건·외부 요청 0건을 기록한다.
