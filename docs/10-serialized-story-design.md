# 상자 친구 연재 이야기 디자인

작성 기준: 2026-10-05. 사용자의 연재 이야기 추가 요청에 따른 HTML 시안의 디자인·내용·저장 규칙입니다. 구현 전 아래 디자인 선택을 먼저 기록한 뒤 구현했습니다. 이야기 24/22와 기존 기능 61/61 검사가 통과했으며 실제 실행 결과는 [연재 이야기 검증](11-serialized-story-verification.md)에서 확인합니다.

## 두 배치안과 선택

큰 이야기 카드와 짧은 초대줄을 비교했습니다. 모두 사용자가 버튼을 눌러야 이야기를 읽고 완료 시 자동 팝업은 띄우지 않습니다.

### 안 A: 대시보드에 큰 이야기 카드

```text
┌──────────────────────────────┬──────────────────┐
│ 오늘의 일일 미션 3개          │ 실제 연결 상태   │
│ 최근 7일 완료 스탬프          │ 계속 미연결 표시 │
├──────────────────────────────┴──────────────────┤
│                                                │
│      큰 상자 친구 그림 · 이번 장면              │
│      장면 제목 · 짧은 이야기 · [계속 읽기]      │
│                                                │
├────────────────────────────────────────────────┤
│ SKU별 채널 재고 비교표                          │
└────────────────────────────────────────────────┘
```

그림과 이야기는 잘 보이지만 방문할 때마다 큰 높이를 차지합니다. 넓은 화면에서도 재고 비교표를 아래로 밀고, 모바일에서는 실제 연결 상태와 비교표에 도달하는 이동량이 늘어납니다. 일일 미션과 또 다른 큰 보상 카드가 경쟁한다는 점도 업무 화면에 맞지 않습니다.

### 안 B: 일일 미션 아래 짧은 이야기 초대줄

```text
┌──────────────────────────────┬──────────────────┐
│ 오늘의 일일 미션 3개          │ 실제 연결 상태   │
│ 최근 7일 완료 스탬프          │ 계속 미연결 표시 │
│ 상자 친구의 여행 · 1/15 [읽기]│                  │
│ ▸ 추가 샘플 연습             │                  │
├──────────────────────────────┴──────────────────┤
│ SKU별 채널 재고 비교표                          │
└────────────────────────────────────────────────┘

사용자가 [읽기]를 누른 뒤
┌────────────────────────────────────────────────┐
│ 상자 친구의 여행 · 허구 이야기            [닫기]│
├────────────────────────┬───────────────────────┤
│                        │ 에피소드 · 컷 제목    │
│ 큰 장면 그림           │ 짧은 본문 두 문장     │
│ 상자 친구와 여행 장소  │ [이전 컷] [다음 컷]   │
├────────────────────────┴───────────────────────┤
│ 컷 선택: 열린 컷은 다시 읽기 · 잠긴 컷은 비활성│
└────────────────────────────────────────────────┘

모바일 읽기 화면
┌──────────────────────┐
│ 제목             [닫기]│
│ 큰 장면 그림         │
│ 에피소드 · 컷 제목   │
│ 짧은 본문 두 문장    │
│ 이전 / 다음 / 컷 선택│
└──────────────────────┘
```

**안 B를 선택합니다.** 대시보드에서는 이야기의 존재와 열린 컷 수만 짧게 알리고, 큰 그림은 읽기를 선택했을 때 보여 줍니다. 재고표와 실제 연결 상태가 기본 화면의 중심에 남습니다. 미열람 상태를 압박하는 빨간 배지나 자동 이동을 붙이지 않고, 열린 이야기는 언제든 다시 읽을 수 있게 합니다.

안 B의 약점은 그림이 첫 화면에서 잘 보이지 않는다는 점입니다. 초대줄에 이야기 제목·열린 컷 수·읽기 동작을 함께 표시해 발견 가능성을 확보합니다. 보상감을 높이기 위해 초대줄을 키우는 대신 읽기 화면에서 큰 상자 친구 그림과 장면마다 다른 배경을 제공합니다.

## 이야기와 해금 규칙

상자 친구가 지도를 따라 편지를 전하고, 등대를 찾아가며, 다음 여행을 약속하는 허구 이야기입니다. 세 에피소드가 각각 다섯 컷으로 이루어져 총 15컷입니다. 상자 친구의 여행·불빛·편지 도착은 실제 재고 회복이나 주문 처리·API 연결 상태를 뜻하지 않습니다.

오늘의 일일 확인 미션이 한국 날짜(`Asia/Seoul`) 기준 `3/3`이 된 날마다 다음 한 컷을 엽니다. 같은 날짜의 반복 완료·새로고침·일일 기록 삭제 후 재완료·다른 탭의 같은 날짜 완료는 한 날짜로 취급하여 중복 해금하지 않습니다. 이야기를 읽는 것 자체는 새 컷을 열거나 일일 진행을 변경하지 않습니다.

도입 시 현재 브라우저에 저장되어 있는 최근 90일 일일 기록 중 `3/3` 날짜도 누적 해금에 반영합니다. 완료 날짜를 중복 없이 모아 최대 15컷까지 엽니다. 일일 기록이 보관 기간을 지나 사라지거나 쉬었다 돌아오더라도 이미 열린 이야기는 유지합니다. 15컷이 모두 열리면 전체 이야기를 다시 읽을 수 있으며 이 버전에는 추가 컷을 제공하지 않습니다.

완료 시 읽기 대화상자를 자동으로 열지 않습니다. 대시보드의 이야기 버튼으로 읽기를 시작합니다. 이미 열린 이전 컷을 선택하거나 순서대로 다시 읽을 수 있고, 잠긴 컷은 선택 버튼을 비활성화하고 상태를 텍스트로 표시합니다. 아직 열린 컷이 없으면 해금 조건을 안내합니다.

## 시각 기준

기존 시스템 한글 글꼴인 `Malgun Gothic`, `Apple SD Gothic Neo`, `Noto Sans KR`, sans-serif를 사용하고 외부 글꼴을 요청하지 않습니다. 본문은 14px, 장면 제목은 20px를 기준으로 합니다. 이야기는 흰색 `#FFFFFF` 바탕, 민트 `#16816A`, 옅은 민트 `#EAF6F1`, 녹회색 `#203C37`, 황갈색 `#976116`, 경계선 `#DCE7E3`를 사용합니다. 황갈색은 여행 소품과 기존 경고 상태에 각각 쓰되 이야기 꾸밈을 운영 경고로 해석하지 않도록 영역을 분리합니다.

장면 그림은 HTML 안의 원작 벡터 SVG로 만들고 외부 이미지를 요청하지 않습니다. 큰 상자 친구와 지도·다리·우체통·등대·종이배 같은 소품으로 장면을 구분합니다. SVG는 장식이며 장면의 의미는 제목과 본문으로 전달합니다. 폭죽·소리·계속 움직이는 그림은 추가하지 않습니다.

넓은 읽기 화면은 왼쪽 그림과 오른쪽 제목·본문으로 나누고 그림은 상단 제목 아래에 둡니다. 모바일에서는 그림 다음에 제목·본문·이동 버튼을 세로로 쌓습니다. 그림이 본문이나 닫기 버튼을 가리지 않으며 읽기 대화상자 안에서 필요한 만큼 이동할 수 있어야 합니다.

## 저장과 지속성

별도 브라우저 저장 키 `stockd.story-progress.v1`을 사용합니다. 저장 형식은 `{ version: 1, unlockedDates: [...], lastViewed: 0 }`이며 해금한 한국 날짜와 마지막으로 읽은 컷 번호만 기록합니다. 상품·주문·계정·개인정보·키·토큰은 저장하지 않습니다.

- `version`은 이 형식의 버전 1입니다.
- `unlockedDates`는 중복 없는 완료 날짜 배열이며 최대 15개입니다. 배열의 날짜 수가 열린 컷 수가 됩니다.
- `lastViewed`는 미열람일 때 0, 읽었을 때 이미 열린 1~15의 컷 번호입니다. 잠긴 컷 번호는 저장하지 않습니다.
- 저장이 허용되는 같은 브라우저·같은 저장 위치에서 새로고침하거나 다시 열면 열린 컷과 마지막 열람 위치를 복원합니다.
- 파일 직접 열기와 HTTP 미리보기는 저장 위치가 달라 기록을 공유하지 않습니다. 서버나 다른 브라우저·기기로 동기화하지 않습니다.

기존 `stockd.daily-checks.v1`의 최근 90일 정리와 이야기 누적 저장은 분리합니다. 일일 기록 삭제·샘플 초기화는 이야기 누적을 지우지 않습니다. 이미 해금한 날짜는 이야기 기록에도 남으므로 같은 날 일일 미션을 삭제하고 다시 완료해도 다음 컷을 추가로 지급하지 않습니다. 여러 탭에서 같은 날짜를 완료해도 날짜 중복을 제거하고 열린 컷을 하나만 추가합니다.

사용자가 별도 이야기 초기화를 요청하지 않았으므로 설정에 이야기 초기화 버튼을 제공하지 않습니다. 브라우저의 해당 저장소를 전체 삭제하면 이야기 기록도 초기화됩니다. 저장이 불가능한 환경에서는 시안을 계속 사용할 수 있고 이야기 진행은 현재 열기에서만 유지된다는 안내를 표시합니다.

## 접근성과 기존 화면 보존

읽기·이전 컷·다음 컷·컷 선택·닫기 동작은 키보드로 조작할 수 있어야 합니다. 버튼은 44px 이상의 조작 영역을 확보하고 잠긴 컷의 상태를 텍스트와 비활성 상태로 전달합니다. 대화상자는 제목을 읽을 수 있고 Escape로 닫은 뒤 원래 이야기 버튼으로 초점이 돌아갑니다.

효과를 끈 설정과 `prefers-reduced-motion`에서도 전체 이야기를 사용할 수 있어야 합니다. 큰 그림이나 잠긴 컷 목록이 모바일 화면 전체를 가로로 넘치지 않아야 합니다. 미션·실제 연결 상태·재고 비교표·추가 샘플 연습의 기존 기능과 수량 의미를 유지합니다.

## 검증 기준

- 당일 `3/3` 전에는 새 컷이 열리지 않고 `3/3`이 되면 한 컷만 열리는지 확인합니다.
- 같은 날 재방문·새로고침·일일 삭제 후 재완료·여러 탭으로 중복 해금되지 않는지 확인합니다.
- 저장된 최근 90일의 완료 날짜가 처음 도입 시 반영되고 최대 15컷을 지키는지 확인합니다.
- 90일 경과·쉬었다 복귀·일일 기록 삭제·샘플 초기화 후에도 이미 열린 이야기가 유지되는지 확인합니다.
- 읽기 버튼을 누를 때만 대화상자가 열리고 이전 열린 컷은 다시 읽을 수 있으며 잠긴 컷은 선택할 수 없는지 확인합니다.
- 마지막 열람 컷 복원과 손상된 저장 데이터·저장 차단 시의 복구 및 안내를 확인합니다.
- 1440px·768px·360px, 키보드·Escape·초점 복귀·움직임 줄이기에서 조작할 수 있는지 확인합니다.
- 실제 API 미연결과 샘플 수량·시각·주문 범위·외부 쓰기 제외가 유지되는지 확인합니다.

기준의 정의와 실행 결과는 구분합니다. 실제 검사별 결과와 화면 확인 범위는 [연재 이야기 검증](11-serialized-story-verification.md)에 기록했습니다.
