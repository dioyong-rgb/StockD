# StockD 화면 시안 기획·디자인

작성 기준: 2026-10-04. `docs/notion-simple/01~05`와 프로젝트 지침에 근거합니다. 실제 API·DB 연결 없이 단일 HTML로 제품 화면을 미리 확인하는 시안입니다.

## 화면이 해야 할 일

운영자가 여러 판매자센터를 오가며 확인하던 옵션별 재고와 주문을 한곳에서 비교합니다. 첫 화면에서 **무엇을 먼저 확인할지**, 재고 화면에서 **어느 판매 경로의 값인지**, 주문 화면에서 **어디까지 조회한 결과인지**가 바로 보여야 합니다.

첫 범위는 네이버 스마트스토어, 쿠팡 판매자배송, 쿠팡 로켓그로스입니다. 판매 경로별 수량은 의미가 다르므로 실제 보유 재고로 합산하지 않습니다. 조회와 내부 상품 연결·설정만 시연하며 쇼핑몰 재고 수정·발송·주문 상태 변경은 제공하지 않습니다.

## 디자인 토큰

색은 아래 여섯 개를 중심으로 사용합니다. 회색 글자와 구분선은 남색의 농도를 낮춰 만들며 추가 장식색을 넣지 않습니다.

| 이름 | 값 | 역할 |
| --- | --- | --- |
| 남색 | `#18324F` | 본문·제목·사이드바 |
| 흰색 | `#FFFFFF` | 표·내용 영역 |
| 옅은 청회색 | `#EFF3F8` | 앱 바탕·표 머리글 |
| 청색 | `#2864D8` | 선택 메뉴·주요 버튼·링크 |
| 녹색 | `#287B63` | 정상 조회 예시·회복 상태 |
| 황갈색 | `#A96017` | 낮은 수량·조회 실패·지연 |

- 글꼴: `"Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`. 외부 글꼴 요청 없이 각 운영체제의 한국어 글꼴을 사용합니다.
- 기본 본문과 표 값 14px 이상, 보조 설명 12~13px, 영역 제목 18px, 페이지 제목 26~28px. 기본 줄 높이 1.55, 숫자는 자릿수 폭을 고정합니다.
- 수량·날짜는 우측 또는 명확한 열 기준으로 정렬하고, 상품명·상태 설명은 좌측 정렬합니다.
- 간격은 4/8/12/16/24/32px. 버튼 높이는 36~40px이며 터치 영역은 44px 이상 확보합니다.
- 입력·버튼 모서리는 6px, 정보 영역은 8px. 모든 영역에 그림자를 넣지 않습니다. 구분선과 제목으로 계층을 나타냅니다.
- 초점 테두리는 청색 2px. 상태는 색 외에 ‘품절’, ‘조회 실패’ 등 텍스트와 아이콘으로도 표시합니다.

## 제품 구조

넓은 화면은 208px 남색 사이드바와 여백이 있는 내용 영역을 사용합니다. 오른쪽 내용은 지나치게 긴 글 대신 표와 짧은 안내로 구성합니다. 주요 메뉴는 대시보드, 통합 재고, 통합 주문, 상품 연결, 알림 예시, 연결·설정입니다. 대시보드의 제목은 ‘오늘 확인할 일’이며 화면 전환 시 제목과 선택 메뉴가 함께 바뀝니다. 실제 시안에서는 알림 확인과 계정 준비의 목적을 구분하기 위해 초기 기획의 알림·연동 메뉴를 두 개로 나눴습니다.

```text
┌────────────┬─────────────────────────────────────────────┐
│ StockD     │ 샘플 데이터 · 실제 API 미연동                 │
│            ├─────────────────────────────────────────────┤
│ 운영 현황  │ 운영 현황              시안 기준 시각          │
│ 통합 재고  │ 상품·옵션 상태를 먼저 확인하세요.               │
│ 통합 주문  ├────────────────────────────┬────────────────┤
│ 상품 연결  │ 확인할 일                  │ 채널 상태 예시 │
│ 알림·연동  │ 부족 수량 / 오래된 조회     │ 스마트스토어   │
│            │ 미연결 옵션                │ 판매자배송 / RG│
│            ├────────────────────────────┴────────────────┤
│ 화면 시안  │ SKU별 채널 재고 비교                          │
│            │ 상품 | 스마트스토어 | 판매자배송 | RG 주문가능 │
│            │      | 각각 다른 수량 의미와 상태              │
└────────────┴─────────────────────────────────────────────┘
```

이 제품의 특징은 같은 판매 단위의 세 판매 경로를 가로로 비교하는 표입니다. 표의 열 제목에 ‘등록 재고’와 ‘주문가능 재고’를 적고, 비교표 아래 ‘채널 수량은 실제 보유 재고로 합산하지 않습니다’라는 안내를 둡니다.

## 화면별 구성과 동작

### 운영 현황

‘오늘 주문 1,000건’ 같은 실제 운영 통계처럼 보이는 큰 숫자 카드는 사용하지 않습니다. 확인할 일 목록과 판매 경로 상태를 먼저 두고, 아래에 재고 비교표를 배치합니다. 목록에서 해당 재고 필터·미연결 옵션·연동 상태 화면으로 이동합니다. 집계가 필요할 때는 ‘샘플에서 확인할 일’ 또는 ‘예시’라고 명시합니다.

### 통합 재고

검색, 판매 경로, 상태 필터와 결과 건수를 표 바로 위에 둡니다. 옵션명·내부 SKU·채널/계정·배송 방식·수량 종류·수량·조회 상태·마지막 성공 시각을 확인합니다. 상품명으로 임의 합산하거나 서로 다른 계정의 옵션을 섞지 않습니다. 행 선택으로 수량의 출처와 조회 이력을 확인하는 상세 패널을 엽니다.

| 수량 예시 | 반드시 함께 보여줄 문구 |
| --- | --- |
| `0` | 품절 · 정상 조회 예시 |
| `12` | 마지막 성공값 · 최근 조회 실패 |
| `—` | 첫 조회 실패 · 확인한 수량 없음 |
| `—` | 재고 관리 미사용 |
| `—` | 미지원 또는 지원 여부 미확인 |

오래된 데이터는 값과 함께 ‘조회 지연’을 표시합니다. 정보가 없는 값을 0으로 표시하지 않습니다. 상단 샘플 띠와 행 출처의 ‘샘플’ 표시를 유지합니다.

### 통합 주문

판매 경로·기간·원본 상태 필터와 주문 행 표를 제공합니다. 샘플 주문번호, 옵션/SKU, 수량, 원본 상태, 채널, 확인 시각을 사용하고 실제 개인정보는 포함하지 않습니다. 부분 취소·반품은 주문 상태와 별도로 보여줍니다. RG에는 ‘출고 이후 조회 범위’와 ‘상태 변경·클레임 지원 미확인’을 표시합니다. 미제공 상태를 ‘정상’, ‘결제 완료’로 추정하지 않습니다.

### 상품 연결

내부 상품 코드와 판매 경로별 원본 옵션 ID의 관계를 보여줍니다. ‘연결됨’과 ‘미연결’을 분리하고 후보는 사용자가 확인한 뒤 확정하는 흐름을 시연합니다. 상품명 일치가 자동 확정을 뜻하지 않습니다. 확인 버튼은 ‘시안에 연결 적용’으로 표시하고 피드백도 이 브라우저의 샘플 관계만 변경했다는 뜻을 전달합니다. 실제 계정 데이터는 변경하지 않습니다.

### 알림·연동

재고 부족·조회 실패·조회 지연의 **알림 예시**와 임계값 설정 시안을 제공합니다. 모든 계정은 실제 미연결 상태이며 별도 ‘조회 상태 시연’에서 성공/실패 예시를 볼 수 있습니다. API 키·토큰 입력창을 만들지 않습니다. 계정 준비·공식 연결 방법을 보기 쉽게 설명할 수 있지만 운영 화면에 엔드포인트나 서버 설정을 노출하지 않습니다.

## 반응형과 접근성

- 960px 미만은 넓은 사이드바를 없애고 상단에 메뉴를 놓습니다. 메뉴가 넘치면 가로로 이동하되 현재 선택 메뉴가 보이도록 합니다.
- 640px 미만은 검색과 필터를 1~2열로, 확인할 일/채널 상태를 한 열로 배치합니다. 긴 표는 가로 스크롤하고 상품 열이 지나치게 좁아지지 않게 합니다.
- 모바일에서 표를 카드로 바꿔 수량 의미를 숨기지 않습니다. 표 앞에 필요한 경우 ‘표를 좌우로 움직여 확인하세요’ 안내를 제공합니다.
- 모든 버튼·입력에 읽을 수 있는 이름을 두고, 활성 메뉴는 보조 기술에도 알려 줍니다. 상세 패널은 Escape로 닫고 닫힌 뒤 원래 행/버튼으로 초점을 돌립니다.
- 화면 전환 후 제목을 명확하게 알리고 빈 검색 결과에는 필터를 초기화하는 동작을 제공합니다.
- 자동 움직임을 넣지 않습니다. 사용자 동작에 따른 짧은 변화만 사용하고 움직임 줄이기 설정을 존중합니다.

## 작성 전 디자인 검토

초기안의 큰 통계 카드 네 개는 제품의 핵심 판단을 가리고 실제 운영 집계로 오해될 수 있어 제거했습니다. 채널별 수량 의미를 확인하는 비교표와 확인할 일 목록으로 바꿨습니다. 모든 내용을 동일한 카드에 넣는 구성도 피하고, 작업 목록·상태 영역·표의 성격에 맞게 밀도를 달리했습니다.

남색 사이드바와 청색 선택 상태는 익숙한 운영 도구의 방향을 따릅니다. 별도의 장식으로 차별화하기보다 SKU별 판매 경로의 수량 의미와 조회 실패를 명확히 드러내는 구성에 개성을 집중합니다. 그라데이션, 반복 그림자, 과장된 숫자, 문서 단계 번호를 운영 화면에 옮기는 방식은 제외했습니다.

HTML 완성 후에는 실제 데스크톱·모바일 화면에서 메뉴의 선택 상태, 표 열 폭, 실패/미확인 상태의 구분, 접힘·상세 패널, 필터와 빈 결과를 검토합니다. 결과와 보완 사항은 이 문서에 추가합니다.

## 실제 시안의 시각 검토

감독자가 1440px와 360px 브라우저 화면을 직접 확인했습니다. 먼저 확인할 일과 SKU별 세 판매 경로 비교가 구분되고, 등록 재고·주문가능 재고·품절·조회 실패·관리 미사용의 의미를 텍스트로 확인할 수 있습니다. 실제 연결 상태는 미연결로 표시합니다.

모바일에서 가로 메뉴의 선택 항목이 화면 밖에 남는 문제를 보완해 선택 메뉴가 보이도록 했습니다. 비교표·재고·주문·상품 연결 표에는 좁은 화면에서 좌우 이동 안내를 표시합니다. 넓은 표는 내부에서 가로 이동하고 전체 페이지는 화면 폭을 유지합니다.

원래 디자인 담당이 화면 기획과 디자인 기준을 작성했고, 구현 담당이 HTML에 반영했습니다. 완성본의 실제 화면 검토는 감독자가, 기능·반응형 검증은 별도 검증 담당이 수행합니다. 자세한 결과는 `prototype-verification.md`에 기록합니다.
