## 요약

첫 버전은 네이버 스마트스토어와 쿠팡을 조회 중심으로 연결하며 재고의 의미·주문 상태·데이터 출처·실패 여부를 구분해야 합니다.

## 1. 조회와 상태 표시

상품·옵션·재고와 지원되는 주문·취소·반품·교환을 조회합니다. 쇼핑몰 재고 수정·발송 처리·주문 상태 변경 같은 외부 쓰기는 제외하며, 조회한 주문 상태만 내부 DB에 반영합니다.

정상 수량 0은 품절로 표시합니다. 첫 조회 실패는 수량 없음과 실패로 표시하고, 성공 후 실패는 마지막 성공값을 유지합니다. 미지원과 재고 관리 미사용은 수량을 비워 구분하며, 지원 여부 미확인도 별도로 표시합니다. 마지막 성공·최근 시도 시각과 오래된 데이터 상태를 보여주고 빈 응답·오류를 0으로 바꾸지 않습니다.

## 2. 상품 연결과 주문

상품명 대신 내부 SKU와 원본 옵션 식별자로 연결하고 운영자가 후보를 확정합니다. 계정 범위를 포함해 같은 외부 ID의 충돌을 막으며, 미연결 옵션과 매핑 변경 이력도 보존합니다.

쿠팡 판매자배송과 로켓그로스를 모두 포함합니다. 채널 등록 재고와 RG 주문가능 재고는 구분하고 실제 보유량으로 합산하지 않습니다. 주문은 행별 수량·원본 상태와 부분 클레임을 보존하고 과거 주문·클레임의 변경도 재확인합니다.

RG 주문은 출고 이후 조회 가능하며 상태 변경·클레임 지원은 미확인입니다. 결제 직후 주문 전체를 수집했다고 표현하거나 미제공 상태를 추정하지 않습니다.

## 3. 출처와 보안

화면은 인증된 서버를 통해 DB를 읽습니다. 전체 페이지 수집과 검증이 완료된 범위만 반영하고, 부분 실패나 워커 중단은 마지막 성공값을 손상시키지 않아야 합니다.

샘플은 상단과 행에 표시하고 운영 통계·부족 재고 알림에서 제외합니다. API 키·토큰은 서버에서만 처리하며 브라우저·문서·샘플·로그에 노출하지 않습니다. 조직·계정 권한을 서버에서 검사하고 불필요한 주문 개인정보는 기본 저장하지 않습니다.

현재는 요건만 정리된 상태이며 실제 기능·API·DB 검증은 이후 진행합니다. G마켓·옥션·11번가는 후속 확장 범위입니다.
